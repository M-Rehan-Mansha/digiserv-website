# DIGISERV
### Digital, Creative & Business Solutions Agency

**One Agency. Multiple Services. Endless Possibilities.**

DIGISERV is a full-service digital, creative, technological, and business solutions agency website designed to present a comprehensive range of professional services through one unified platform.

The platform showcases DIGISERV's services, departments, portfolio, pricing packages, and business capabilities while providing prospective clients with dedicated contact, quotation, and consultation workflows.

Built with React, TypeScript, Vite, Tailwind CSS, and an Express backend, the website combines a modern responsive interface with dynamic content management and inquiry handling.

## Client Inquiry System

The website provides a centralized inquiry system for potential clients.

### Supported Inquiry Types

- General contact.
- Project quotation.
- Professional consultation.
- Package inquiries.

### Information Collected

- Full name.
- Email address.
- WhatsApp number.
- Country.
- Company name.
- Required service.
- Project budget.
- Preferred contact method.
- Project description.
- Selected package information, where applicable.
- Consultation date and timezone, where applicable.
- Selected sub-services.
- Privacy consent.

### Inquiry Processing

1. The visitor completes the relevant inquiry form.
2. Client-side form handling sends the information to the backend.
3. The backend validates required information.
4. Invalid email addresses and incomplete submissions are rejected.
5. A honeypot field provides basic spam protection.
6. A unique inquiry record is generated.
7. The inquiry is saved in the application data store.
8. An optional configured CRM webhook receives the inquiry.
9. The visitor receives a submission confirmation.

The backend retains up to 250 inquiry records in its current storage implementation.

## Getting Started

Follow these instructions to run DIGISERV locally.

### Prerequisites

Install the following:

- Node.js (a modern supported version).
- npm or Bun.
- Git.
- Visual Studio Code or another code editor.

### 1. Clone the Repository

```bash
git clone https://github.com/M-Rehan-Mansha/digiserv-website.git
```

### 2. Navigate to the Project

```bash
cd digiserv-website
```

### 3. Install Dependencies

Using npm:

```bash
npm install
```

Alternatively, using Bun:

```bash
bun install
```

The repository includes a `bun.lock` file for Bun dependency management.

### 4. Configure Environment Variables

Create a `.env` file in the project root.

You can start with:

```bash
cp .env.example .env
```

On Windows PowerShell, use:

```powershell
Copy-Item .env.example .env
```

Configure the required values according to your environment.

### 5. Start the Development Server

Using npm:

```bash
npm run dev
```

Or using Bun:

```bash
bun run dev
```

The application starts on:

```text
http://localhost:3000
```

The development server uses Express with Vite middleware.

## Backend API

The Express backend provides the following API endpoints.

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/health` | API health check |
| GET | `/api/settings` | Retrieve agency settings |
| PUT | `/api/settings` | Update agency settings |
| GET | `/api/content` | Retrieve portfolio, FAQs and testimonials |
| PUT | `/api/content` | Update website content |
| GET | `/api/inquiries` | Retrieve submitted inquiries |
| POST | `/api/inquiries` | Submit a new inquiry |

### Health Check

```http
GET /api/health
```

Example response:

```json
{
  "ok": true,
  "service": "digiserv-api"
}
```

### Submit an Inquiry

```http
POST /api/inquiries
Content-Type: application/json
```

The endpoint validates inquiry information, checks privacy consent, applies basic honeypot spam protection, generates a unique record, and stores the submission.

### Optional CRM Integration

The backend supports forwarding newly submitted inquiries to a configured CRM webhook URL.

This allows future integration with external CRM and business automation platforms.

## Privacy and Security

The application includes basic privacy and security measures.

### Existing Measures

- Server-side email validation.
- Server-side required-field validation.
- Input length restrictions.
- Basic honeypot spam protection.
- JSON request size limit.
- `X-Content-Type-Options: nosniff`.
- `Referrer-Policy: strict-origin-when-cross-origin`.
- Cookie consent preference storage.
- Privacy consent requirement for inquiries.
- Environment-based configuration.

### Important Production Considerations

Before using the platform for real customer information, the following improvements are recommended:

1. Implement proper administrator authentication.
2. Add server-side authorization to administrative APIs.
3. Replace JSON file storage with a reliable production database.
4. Add rate limiting and stronger spam prevention.
5. Implement secure session management.
6. Validate and restrict CRM webhook destinations.
7. Introduce automated backups.
8. Implement appropriate data retention and deletion policies.
9. Add comprehensive server-side error logging.
10. Configure production HTTPS and security headers.

The existing JSON file storage is suitable for development and limited environments, but should not be relied upon as durable storage on ephemeral or serverless hosting platforms.
